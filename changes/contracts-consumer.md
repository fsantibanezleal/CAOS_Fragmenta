- The TypeScript types of the app are generated from the contract schemas: `frontend/scripts/gen-contract-types.mjs` writes `src/lib/contract.gen.ts` from `docs/contracts/api.openapi.json` with `openapi-typescript` 7.13.0 (pinned exactly), and `npm run build` runs it with `--check` first, so a schema change without a regeneration stops the build. `src/lib/contract.types.ts` is now aliases of the generated types, no longer a 544-line hand mirror; the generated types are more exact than the mirror was (the models-file arms and their fields, the four controls, `cv` and `n_simulations` always present, null draws and seed scores), and `Benchmark.tsx` drops null draws and null seed scores before it plots them.
- The consumer and swap tests: `src/lib/contract.test.ts` holds the committed bake and the provider tree to the schemas in both directions (a field the schema does not name, a required field that is absent, a wrong type, and an absent document each fail naming the path) and the catalog to the generated components; `parity.test.ts` now reads the field names from the generated file.
- The six readiness states in the interface (`frontend/src/readiness/`, template 0.08.002): a view's note comes from `readiness.json`, a case or file the document lists as absent is refused with its reason instead of drawn empty, the case selector marks an absent case "not available yet", and an available build shows nothing new. `ReadinessTable` is placed in the Implementation page's contract area.
- `frontend/copy-data.mjs` copies exactly the files the index declares plus `readiness.json`, rebuilds the overlay from scratch, and accepts an absent manifest, artifact or models file only when a `partial` row of the readiness document lists it; any other absence, and an absent readiness document, stops the build.
